# Python SDR Scripts for the AERPAW Digital Twin

Python scripts for I/Q collection, spectrum monitoring and link measurements on the virtual USRP (V-USRP) radios of the [AERPAW](https://aerpaw.org) digital twin. AERPAW is the Aerial Experimentation and Research Platform for Advanced Wireless at NC State University.

These scripts accompany **Report-5: Python SDR Scripts for AERPAW** ([docs/Report-5_Python_SDR_Scripts_AERPAW.pdf](docs/Report-5_Python_SDR_Scripts_AERPAW.pdf)). The report is part of a series of reports on experiments in the AERPAW digital twin, prepared for the AERPAW Open Research on Autonomy (AORA) challenge. The report explains the background for new users, the rules of the twin, each script, the test results and the commands to reproduce them.

## Requirements

The scripts target the software image of the AERPAW experiment nodes:

- Ubuntu 22.04, Python 3.10
- UHD 4.9 with its Python bindings (`import uhd`)
- NumPy and SciPy, Matplotlib for the optional plots
- The AERPAW `pychem` client (CHEM functions only)
- iperf3 and ping (`link_logger.py` only)

They run on the CPU only. The offline modes (analysis of saved records, `meters.py`, `ds_manifest.py`, `mat2sigmf.py`, `siggen.py --save`) also run on a normal Linux, macOS or Windows computer with NumPy and SciPy.

## Quick start on an AERPAW node

1. Copy the `scripts/` folder to the node, for example to `~/aerpaw_py/`.
2. Source the experiment environment file, so that the scripts can find CHEM:
   ```bash
   source /root/.ap-set-experiment-env.sh
   ```
3. Run the self-test on the TX node and on the RX node:
   ```bash
   python3 preflight.py check
   python3 preflight.py tx --secs 10     # on the fixed node, for example FN1
   python3 preflight.py rx               # on the drone node, for example PN1
   ```
4. Send a test signal and record it:
   ```bash
   python3 siggen.py tone --secs 30                                   # TX node
   python3 iq_recorder.py rec1 --secs 10 --link 'M1>M3' --label first  # RX node
   ```
5. Measure the SNR of a QPSK signal over a CHEM fixed-SNR sweep:
   ```bash
   python3 siggen.py qpsk --save qpsk_ref.c64          # reference period, no radio
   python3 siggen.py qpsk --secs 300                   # TX node
   python3 chem_sweeper.py noise 30,20,10,0 --link 'M1>M3' --ref qpsk_ref.c64 --mod qpsk   # RX node
   ```

The `--link` value is the CHEM name of a link (TX node > RX node). In our experiment, `M1>M3` was the link from FN1 to PN1. Check the link names that your CHEM shows. Each script has `--help`. Section 5 of the report gives a full "first hour" path through the scripts.

## Rules of the digital twin

The V-USRP and CHEM have rules that differ from a real USRP. `vusrp_io.py` enforces most of them in code. Section 4 of the report explains each rule and its evidence.

- **TX frequency.** TX works only in these ranges (MHz): 6.765–6.795, 13.553–13.567, 26.957–27.283, 40.66–40.70, 433.05–434.79, 860–880, 902–928 and 3300–3450. The V-USRP refuses other frequencies.
- **Sample rate.** Use 1 to 23.04 MS/s.
- **Continuous streams.** Use continuous RX. Finite RX bursts can return 0 samples without an error. Use continuous TX with zero fill between bursts.
- **No retune.** Set the rate, frequency and gain once before you start a stream.
- **Absolute gains and sc16.** Use the sc16 wire format. sc8 and normalized gains do not work.
- **Skip the first second.** The first second of an RX record can show a 0-m link.
- **Timing.** CHEM acts about 0.5 s after a command. Time-stamp on the node clocks.
- **Late samples.** The twin can deliver RX samples late, in steps of about 1 ms. Use `iq_recorder.py --lag-log` to check.
- **Channel model limits.** CHEM applies one Doppler shift for each link (no Doppler spread). It does not add the absolute delay of the distance. Multipath taps are in whole samples.
- **Measured SNR.** The measured SNR of a bursty signal differs from the CHEM fixed-SNR value by about ±3 dB.
